Title:
New file: reusable untargetability filter (stealth/elusive) for interactive target picking

Purpose:
Today, stealth/elusive untargetability is only enforced inside `PlayCardAction.IsValid` as a special case for card plays — there is no equivalent gate for a triggered ability's interactive target selection (e.g. "on attack, select a minion, deal 3 damage" has no `PlayCardAction` in its resolution chain at all). This task extracts that rule into a small reusable helper that the new generic `TargetSelectionChoice` (task NTR-003) can call, so untargetability is honored uniformly for every interactive pick, not just card plays.

Dependencies:
(none — only depends on pre-existing, unmodified types: `IGameEntity`, `Minion`, `Player`)

Consumes:
(none)

Produces:
A reusable filtering helper, consumed by NTR-003 (`TargetSelectionChoice.GetActions` calls it when building the candidate pool for any interactive pick).

Files:
CardBattleEngine\CastRestictions\UntargetableFilter.cs (new file)

Requirements:
Create a new static helper class:
```csharp
namespace CardBattleEngine;

public static class UntargetableFilter
{
    public static IEnumerable<IGameEntity> ExcludeUntargetable(IEnumerable<IGameEntity> candidates, Player picker)
    {
        return candidates.Where(e => !(e is Minion m && (m.IsStealth || m.Elusive) && m.Owner != picker));
    }
}
```
This must reproduce exactly the same logic already used in `PlayCardAction.IsValid`'s stealth/elusive check (look at that method — it was last touched by tasks FWD-008 and NTR-008 — to confirm the exact condition being mirrored here: an enemy minion that is stealthed or elusive relative to the picking player is excluded). If `PlayCardAction`'s actual condition differs even slightly from what's shown above (e.g. additional keyword checks), match `PlayCardAction`'s real condition exactly rather than the illustrative snippet above.

Constraints:
- Do not modify `PlayCardAction.cs` in this task — this is a new, separate, reusable helper only. `PlayCardAction`'s own existing single-target stealth/elusive check (already correct for single-target card plays) is left untouched; this helper is for the new generic multi-pick/trigger-pick path only.
- Do not add any other filtering rule beyond stealth/elusive matching — no additional untargetability logic invented here.

Acceptance Criteria:
- `UntargetableFilter.ExcludeUntargetable` excludes any `Minion` that is stealthed or elusive and not owned by the picking player, from a candidate list, and passes through every other entity (including friendly stealthed/elusive minions, and non-minion entities like `Player`) unchanged.
- The logic exactly matches the existing condition already enforced in `PlayCardAction.IsValid`.

Validation:
Run `dotnet build CardBattleEngine.sln` — should succeed (new, self-contained file, no existing callers yet).

Handoff:
Task NTR-003 depends on this file and calls `UntargetableFilter.ExcludeUntargetable` when building candidate pools for interactive target selection.
