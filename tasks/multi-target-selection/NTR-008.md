Title:
PlayCardAction.IsValid: validate the full Targets list against RequiredTargetCount

Purpose:
Task FWD-008 kept `PlayCardAction.IsValid` checking only the first entry of `Targets` (behavior-preserving for single-target cards). By the time `IsValid` runs on a multi-target card play, `GameEngine.Resolve`'s central interception (NTR-005) has already guaranteed `Targets` is fully populated to `RequiredTargetCount` — so this task upgrades the check to validate the whole list as a final safety net: count and pool membership.

Dependencies:
FWD-008, NTR-006

Consumes:
FWD-008: mechanically-renamed `PlayCardAction.cs`. NTR-006: `Card.RequiredTargetCount`.

Produces:
Real multi-target validation in `IsValid`, exercised by the POC-002 test.

Files:
CardBattleEngine\Actions\PlayCardAction.cs

Requirements:
Locate the target-membership check that FWD-008 left single-target-only, e.g.:
```csharp
var validTargets = Card.ValidTargetSelector?.Select(state, actionContext.SourcePlayer, Card)?.ToList();
if (validTargets != null && validTargets.Any())
{
    if (!validTargets.Contains(actionContext.Targets?.FirstOrDefault()))
    {
        reason = "Invalid Target";
        return false;
    }
}
```
Replace the inner check with full-list validation:
```csharp
var validTargets = Card.ValidTargetSelector?.Select(state, actionContext.SourcePlayer, Card)?.ToList();
if (validTargets != null && validTargets.Any())
{
    var chosen = actionContext.Targets ?? new List<IGameEntity>();
    if (chosen.Count != Card.RequiredTargetCount || chosen.Any(t => !validTargets.Contains(t)))
    {
        reason = "Invalid Target";
        return false;
    }
}
```
Leave the existing stealth/elusive check (already single-target-only, matching `FirstOrDefault()` behavior, from FWD-008) exactly as it is — do not touch it in this task. That check remains a defense-in-depth safety net specifically for the single-target card-play path; the equivalent rule for the new multi-pick/trigger-pick path already lives in the reusable `UntargetableFilter` (task NTR-011), applied at candidate-selection time by `TargetSelectionChoice` (NTR-003) — duplicating it again here isn't necessary and is out of scope for this task.

Constraints:
- Scope this diff to exactly this one file, exactly this one check.
- Do not change the `reason` string values unless matching existing conventions requires it.
- Do not touch any other part of `PlayCardAction` (e.g. `Resolve`, mana-spending logic, or the stealth/elusive check).
- For every existing single-target card (`RequiredTargetCount == 1`), this upgraded logic must produce identical pass/fail results to before — `chosen.Count != 1` combined with the existing single-element `Contains` check is equivalent to the old `FirstOrDefault()`-based check when exactly one target was chosen.

Acceptance Criteria:
- A card with `RequiredTargetCount == 2` is rejected if fewer or more than 2 targets were chosen, or if any chosen target isn't in the legal candidate pool.
- Every existing single-target card's validation behavior is unchanged.

Validation:
Run `dotnet build CardBattleEngine.sln` — should succeed. Run the full test suite — no existing single-target test should change behavior. The new multi-target validation logic itself is exercised by the POC-002 test.
