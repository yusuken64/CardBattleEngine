Title:
TriggerEffectAction: branch on TargetRequirement to enable interactive targeting for triggered abilities

Purpose:
This is what makes "whenever this minion attacks, select a minion, that minion takes 3 damage" actually work. `TriggerEffectAction.Resolve` currently only knows how to hand off to a fully-programmatic `AffectedEntitySelector`. This task adds the alternative path: when the triggered effect instead declares a `TargetRequirement`, `TriggerEffectAction` yields its `GameAction`s with `PendingTargetRequirement` set (and `Targets` left unset) instead of `AffectedEntitySelector` — `GameEngine.Resolve`'s central interception (NTR-005) then automatically pauses and prompts the player when that action is dequeued, exactly as it does for a multi-target card play.

Dependencies:
NTR-001, NTR-012, FWD-007

Consumes:
NTR-001: `ActionContext.PendingTargetRequirement`. NTR-012: `TriggeredEffect.TargetRequirement`. FWD-007: mechanically-renamed `TriggerEffectAction.cs` (sequencing after it avoids merge conflicts on the same file).

Produces:
Interactive targeting for triggered abilities, exercised end-to-end by the POC-003 test.

Requirements:
1. Update `IsValid` to accept either mechanism, not just `AffectedEntitySelector`:
```csharp
public override bool IsValid(GameState gameState, ActionContext context, out string reason)
{
    reason = null;
    return TriggeredEffect.AffectedEntitySelector != null || TriggeredEffect.TargetRequirement != null;

```
2. Update `Resolve` to branch between the two mechanisms:
```csharp
public override IEnumerable<(IGameAction, ActionContext)> Resolve(GameState state, ActionContext context)
{
    if (TriggeredEffect.TargetRequirement != null)
    {
        foreach (var action in TriggeredEffect.GameActions)
        {
            yield return (action, new ActionContext
            {
                Source = TriggerSource.Entity,
                SourcePlayer = TriggerSource.Entity.Owner,
                SourceCard = TriggerSource.Entity is Minion m ? m.OriginalCard : null,
                PendingTargetRequirement = TriggeredEffect.TargetRequirement,
                OriginalAction = context.OriginalAction,
                OriginalSource = context.Source,
            });
        }
        yield break;
    }

    if (TriggeredEffect.AffectedEntitySelector == null) yield break;

    foreach (var action in TriggeredEffect.GameActions)
    {
        yield return (action, new ActionContext
        {
            Source = TriggerSource.Entity,
            SourcePlayer = TriggerSource.Entity.Owner,
            AffectedEntitySelector = TriggeredEffect.AffectedEntitySelector,
            Targets = context.Targets,
            OriginalAction = context.OriginalAction,
            OriginalSource = context.Source,
        });
    }
}
```
Confirmed: `Minion.OriginalCard` (`CardBattleEngine\Entities\Minion.cs:7`) is the correct property — `minion.OriginalCard` is already used identically elsewhere in this codebase (e.g. `Actions\DeathAction.cs:71: SourceCard = minion.OriginalCard,`), so `TriggerSource.Entity is Minion m ? m.OriginalCard : null` above is correct as written; do not substitute a different property name. `SourceCard` needs to be populated correctly here because `TargetRequirement.Provider` (an `IValidTargetSelector`) is called as `Provider.Select(state, player, context.SourceCard)` later on by `TargetSelectionChoice` (task NTR-003) — for a plain `EntityTypeSelector`-style provider (which ignores its `Card` argument entirely) this doesn't matter, but populate it correctly regardless for correctness and for any future selector that does inspect the card.
