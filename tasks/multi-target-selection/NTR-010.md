Title:
CastSpellAction: add a passthrough branch that carries the full Targets list without fan-out when no selector is set

Purpose:
Today, every existing `SpellCastEffect` sets a non-null `AffectedEntitySelector`, so `CastSpellAction` always fans out into per-target contexts. To support an effect like "swap health of 2 picked minions" that needs to see BOTH targets in a single context at once (not two separate single-target contexts), this task adds a new branch: when `AffectedEntitySelector` is null, pass `context.Targets` straight through as one context, unmodified.

FWD-001

Consumes:
FWD-001: mechanically-renamed `CastSpellAction.cs` (sequencing after it avoids merge conflicts on the same file).

Produces:
The "selector == null: passthrough" branch, consumed by task POC-001 (the `SwapHealthAction` proof-of-concept card intentionally leaves `AffectedEntitySelector` null on its `SpellCastEffect` so its action sees the full picked-targets list).

Files:
CardBattleEngine\Actions\CastSpellAction.cs

Requirements:
Inside the loop over `spellcard.SpellCastEffects`, before the existing branch that checks `selector.ResolutionTiming`, add a new branch for when `selector` (the effect's `AffectedEntitySelector`) is null:
```csharp
foreach (SpellCastEffect spellCastEffect in spellcard.SpellCastEffects)
{
    var selector = spellCastEffect.AffectedEntitySelector;

    if (selector == null)
    {
        var spellActionContext = new ActionContext
        {
            SourcePlayer = context.SourcePlayer,
            Source = context.Source,
            SourceCard = context.SourceCard,
            Targets = context.Targets,
        };
        foreach (var action in spellCastEffect.GameActions)
            yield return (action, spellActionContext);
        continue;
    }

    if (selector.ResolutionTiming == TargetResolutionTiming.Once)
    {
        // ... existing fan-out-per-resolved-target branch, unchanged ...
    }
    else
    {
        // ... existing PerAction branch, unchanged ...
    }
}
```
Do not change the existing `Once`/`PerAction` branches at all — only insert the new `selector == null` branch ahead of them. This new branch is genuinely new code, not a changed path for any existing card, because every existing `SpellCastEffect` in current content sets a non-null `AffectedEntitySelector`.
