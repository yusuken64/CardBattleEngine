Title:
Update ValidTargetRestriction to require enough valid targets for RequiredTargetCount, not just one

Purpose:
Today a card is castable if it has at least one valid target. For a multi-target card ("pick 2 minions"), the card should only be castable if at least `RequiredTargetCount` distinct valid targets exist on the board — otherwise the player could begin selection and get stuck unable to finish.

Dependencies:
NTR-006

Consumes:
NTR-006: `Card.RequiredTargetCount`.

Produces:
(none — leaf fixup, but a correctness-critical one)

Files:
CardBattleEngine\CastRestictions\ValidTargetRestriction.cs

Requirements:
In `ValidTargetRestriction.CanPlay` (or equivalently-named method), find the existing check:
```csharp
var validTargets = selector.Select(gameState, player, castingCard);
if (!validTargets.Any())
{
    reason = "No valid targets";
    return false;
}
```
Change it to:
```csharp
var validTargets = selector.Select(gameState, player, castingCard);
if (validTargets.Count() < castingCard.RequiredTargetCount)
{
    reason = "No valid targets";
    return false;
}
```
Since `RequiredTargetCount` defaults to `1`, `Count() < 1` is exactly equivalent to `!Any()` for every existing card — this is a behavior-preserving change for all current content and only changes behavior for a card that explicitly sets `RequiredTargetCount > 1`.

Constraints:
- Scope this diff to exactly this one file, exactly this one check.
- Do not change the `reason` message text unless the existing code already varies it.
- Do not add any other new restriction logic.

Acceptance Criteria:
- The check compares `validTargets.Count()` against `castingCard.RequiredTargetCount`, not against zero/`.Any()`.
- Every existing (single-target, `RequiredTargetCount == 1`) card's castability is unchanged.

Validation:
Run `dotnet build CardBattleEngine.sln` — should succeed. Existing tests exercising `ValidTargetRestriction` must still pass unchanged.

Handoff:
