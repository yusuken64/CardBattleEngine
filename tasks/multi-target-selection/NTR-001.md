Task ID:
NTR-001

Model:
haiku

Title:
Add TargetRequirement class and ActionContext.PendingTargetRequirement field

Purpose:
This is the foundational data shape for the new general-purpose targeting design: ANY action (a card play, a triggered ability's damage effect, anything) can declare "I need the player to pick N targets from this candidate pool before I can resolve" by attaching a `TargetRequirement` to its `ActionContext`. This single field is what `GameEngine.Resolve`'s central loop (task NTR-005) will check before resolving any action.

Dependencies:
(none — foundational, like CTX-000 was for Phase A)

Consumes:
(none)

Produces:
The `TargetRequirement` class and `ActionContext.PendingTargetRequirement` field, consumed by: NTR-003 (`TargetSelectionChoice` reads `Requirement.Provider`/`Count`/`AllowDuplicateTargets`), NTR-005 (`GameEngine.Resolve`'s central interception check), NTR-007 (`GameState.GetValidActions` sets it for multi-target card plays), NTR-012/NTR-013 (`TriggeredEffect`/`TriggerEffectAction` set it for triggered abilities that need interactive target selection).

Files:
CardBattleEngine\Interfaces\GameActionBase.cs
CardBattleEngine\CastRestictions\TargetRequirement.cs (new file)

Requirements:
1. Create a new file `CardBattleEngine\CastRestictions\TargetRequirement.cs`:
```csharp
namespace CardBattleEngine;

public class TargetRequirement
{
    public IValidTargetSelector Provider { get; set; }
    public int Count { get; set; } = 1;
    public bool AllowDuplicateTargets { get; set; } = false;
}
```
Place it in the `CastRestictions` namespace/folder alongside `IValidTargetSelector.cs` since it directly wraps that existing interface — do not invent a new selector interface, reuse `IValidTargetSelector` as-is (its `Select(GameState, Player, Card)` signature already works for both card-driven and trigger-driven cases, since `Card` can be `context.SourceCard`, which every `ActionContext` already carries regardless of whether the action originated from a card play or a triggered ability).
2. In `CardBattleEngine\Interfaces\GameActionBase.cs`, add to the `ActionContext` class:
```csharp
public TargetRequirement PendingTargetRequirement;
```
Add it near the `Targets` field. Do NOT add it to the copy constructor's explicit list unless the constructor copies every field generically — check the existing copy constructor and follow whatever convention it already uses for fields like `Modifier`/`AffectedEntitySelector` (reference copy, not deep copy).

Constraints:
- Do not modify `IValidTargetSelector.cs` itself.
- Do not add any resolution/interception logic in this task — this is purely the data shape. The behavior that acts on this field is added by NTR-005.
- `TargetRequirement` is a plain data class — no methods, no validation logic.

Acceptance Criteria:
- `TargetRequirement` exists with exactly `Provider` (`IValidTargetSelector`), `Count` (`int`, default `1`), `AllowDuplicateTargets` (`bool`, default `false`).
- `ActionContext.PendingTargetRequirement` exists as a nullable reference field of type `TargetRequirement`, defaulting to `null` (i.e., not set) for every existing action construction site — this is purely additive and changes no existing behavior since nothing sets it yet.

Validation:
Run `dotnet build CardBattleEngine.sln` — should succeed (purely additive, no existing code references this new field yet).

Handoff:
NTR-003, NTR-005, NTR-007, NTR-012, and NTR-013 all depend on this task.
